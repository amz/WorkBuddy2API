# Plan: Perf Batch 1 (#1–#5)

## Goal
Cut ~70–100 ms of per-request latency in the WorkBuddy2API proxy by: single-pass request-body handling (#2), zero-cost disabled logging (#3), proper connection-pool sizing (#5), correct DNS fallback + real IP randomization (#4), and a byte-scan SSE hot path (#1). Scope is exactly these five; #8/#9/#10/#11 are deferred.

## Architecture
Single Go module (`main` package). Request flow: `handleChat` (server.go) validates + rewrites the body, `UpstreamClient.Chat` (upstream.go) sends it with `stream:true`, SSE lines stream back through `copySSELogged`'s hot loop which normalizes/decodes each `data:` line via helpers in server.go. Auth/DNS in auth.go, tracing in logging.go.

## Tech Stack
Go 1.27.4 (`~/.local/go` — run tests with `PATH=$HOME/.local/go/bin:$PATH`), stdlib only. Tests with plain `go test`.

## Spec
`docs/superpowers/specs/2026-11-13-perf-batch-1-design.md` — authoritative for all details, including accepted divergences of #1. This plan references it; where this plan is thinner, the spec wins.

## Global Constraints
- TDD per task: failing test first → run to see it fail → implement → run to pass → commit.
- Never commit to master/main; work on branch `ai/perf-batch-1`.
- `sse_stream_test.go` (15 tests) must pass unchanged throughout — it is the #1 safety net.
- Current 400 validation messages must be preserved byte-for-byte: `"model is required"`, `"messages must not be empty"`, `"request body must be valid JSON"` (covers `"stream":"true"`).
- Upstream only supports streaming: proxy always sends `stream:true` upstream and assembles JSON for non-stream clients — preserve.
- No new dependencies. `finishReasonFromLine` (logging.go) stays JSON-based.

## Review Focus
One must-pass line per fix, each pinned by a test in its owning task:
- #2: `chatWithOptions` marshals the payload exactly once; probe path keeps `stream:false` behavior — pinned by `TestChatWithOptions_ProbeKeepsStreamFalse` + `validation_test.go` 400s.
- #3: with logging disabled, no `fmt`/summarise work runs — pinned by `TestLogLine_DisabledIsZeroCost` (mutex-less fast path) and existing `logging_test.go`.
- #5: transport has `MaxIdleConnsPerHost:32`, `MaxIdleConns:100` — pinned by `TestNewHTTPClient_TransportPoolSizes`.
- #4: `failingResolver` dial uses a live IP from `knownUpstreamIPs`, and `pickIP` varies — pinned by `TestPickIP_Rotates` + `TestDialContext_FailingResolverUsesKnownIPs`.
- #1: `normalizeIntermediateFinishReason` output byte-identical to old behavior except `""`→`null` — pinned by `sse_scan_test.go` byte-exact cases + full `sse_stream_test.go`.
